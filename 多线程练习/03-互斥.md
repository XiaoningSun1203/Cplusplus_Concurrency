# 第 3 章：互斥

互斥的意思是：某个“共享资源”在某个时刻只能被一个线程持有（因为成员函数lock()的特性），不能多个线程同时持有。

3.1类std::mutex有3个成员函数：

+void lock()  // 首先，检测std::mutex对象是否已经lock，

Case1:如果mutex对象未lock，则对这个对象进行lock。

Case2:如果已经lock，则陷入等待，直到 mutex 对象被unlock后，才再次lock.

+bool try_lock() // 在上锁失败时不会陷入等待，而是直接返回 false；如果上锁成功，则会返回 true.

+void unlock()   // 解锁

std::mutex mtx;  // 创建 mutex 对象

保证 mtx.lock() 和 mtx.unlock() 之间的代码段，同一时间只能被一个线程操作，从而避免数据竞争data race。

根据 RAII 思想，可将“锁的持有”视为资源，lock()视为锁的获取，unlock()视为锁的释放。

std::lock_guard类 就是这样一个工具类，类的构造函数里会调用 mtx.lock()，解构函数会调用 mtx.unlock()。从而退出函数作用域}时能够自动解锁，避免程序员粗心不小心忘记解锁。

std::lock_guard 严格在解构时 unlock()，但是有时候我们会希望提前 unlock()。

这时可以用 std::unique_lock类，他额外存储了一个 flag 表示是否已经被释放。他会在解构检测这个 flag，如果没有释放，则调用 unlock()，否则不调用。然后可以直接调用 unique_lock 的 unlock() 函数来提前解锁，但是即使忘记解锁也没关系，退出作用域时候他还会自动检查一遍要不要解锁。


```cpp
#include <iostream>
#include <vector>
#include <thread>
#include <mutex>
using namespace std;
int main()
{
    std::vector<int> arr;
    std::mutex mtx;
    std::thread t1([&] {
        for (int i = 0; i < 100; ++i)
        {
            std::unique_lock grd(mtx);
            arr.push_back(1);
        } // 离开grd外面的一层花括号，调用解构函数unlock。
    });
    
    std::thread t2([&] {
        for (int i = 0; i < 100; ++i)
        {
            std::unique_lock grd(mtx);
            arr.push_back(2);
            grd.unlock();  // 解锁
            std::cout << "t2 :out of lock\n";
            grd.lock();  // 如果需要，还可以重新上锁
		    std::cout << "t2 :again lock\n";
        }  // 离开grd外面的一层花括号，调用解构函数unlock。
    });
    
    t2.join();
    t1.join();
    return 0;
}
```

try_lock()

lock() 如果发现 mutex 已经上锁的话，会等待mutex直到unlock。

用 try_lock()，在上锁失败时不会陷入等待，而是直接返回 false；如果上锁成功，则会返回 true。

用法：std::mutex对象.try_lock()


```cpp
#include <iostream>
#include <thread>
#include <mutex>
using namespace std;

int main()
{
    std::mutex mtx;
    if (mtx.try_lock())
        std::cout << "lock success.\n";
    else
        std::cout << "failed.\n";
        
    if (mtx.try_lock())  // mtx在前面已经上锁，此处无法再lock，return false。
       std::cout << "lock success.\n";
    else
        std::cout << "failed.\n";
    
    mtx.unlock();
    mtx.lock();
    if (mtx.try_lock())
        std::cout << "lock success.\n";
    else
        std::cout << "failed.\n";

    return 0;
  // 输出：
// lock success.
     // failed.
     // failed.
}
```

用 std::try_to_lock 做std::unique_lock的参数

和无参数相比，std::try_to_lock会调用 mtx1.try_lock() 而不是 mtx1.lock()。之后，可以用 std::unique_lock对象.owns_lock() 判断是否上锁成功。


```cpp
#include <iostream>
#include <thread>
#include <mutex>
using namespace std;

int main()
{
    std::mutex mtx;
    std::thread thread1([&] {
        std::unique_lock unilock(mtx, std::try_to_lock);

        if (unilock.owns_lock())
            std::cout << "t1: lock success\n";
        else
            std::cout << "t1: failed\n";
    });
    std::thread thread2([&] {
        mtx.lock();  // 导致下一行的unilock 无法lock成功
        std::unique_lock unilock(mtx, std::try_to_lock);

        if (unilock.owns_lock())
            std::cout << "thread2: lock success\n";
        else
            std::cout << "thread2: failed\n";
    });

    thread1.join();
    thread2.join();
    return 0;
    // 输出：
// thread1: lock success
       // thread2: failed
}
```

timed_mutex::try_lock_for()

try_lock() 碰到已经上锁的情况，会立即返回 false。

如果需要等待，但仅限一段时间，可以用 std::timed_mutex 的 try_lock_for() 函数，他的参数是最长等待时间，同样是由 chrono 指定时间单位。

同理还有接受时间点的 try_lock_until().

+bool std::timed_mutex::try_lock_for() // 在上锁失败时允许最长等待指定的时间段，超过这个时间还没成功就会“不耐烦地”失败并返回 false；如果这个时间内上锁成功则返回 true。


**图 12｜标准库声明截图：timed_mutex 的 try_lock_for 接口** — [查看原始截图](images/image12.png)


```cpp
class timed_mutex : private __mutex_base {
public:
    timed_mutex() = default;
    timed_mutex(const timed_mutex&) = delete;
    timed_mutex& operator=(const timed_mutex&) = delete;

    void lock();
    bool try_lock() noexcept;
    template <class _Rep, class _Period>
    bool try_lock_for(const std::chrono::duration<_Rep, _Period>& timeout);
};
```


```cpp
#include <iostream>
#include <thread>
#include <mutex>
using namespace std;

int main()
{
    std::timed_mutex mtx;

    auto time1 = std::chrono::steady_clock::now();
    if (mtx.try_lock_for(std::chrono::seconds(5)))
        std::cout << "lock success.\n";
    else
        std::cout << "failed.\n";
    auto time2 = std::chrono::steady_clock::now();
   cout << std::chrono::duration_cast<std::chrono::seconds>(time2 - time1).count() << endl;
    
    if (mtx.try_lock_for(std::chrono::seconds(5)))
        std::cout << "lock success.\n";
    else
        std::cout << "failed.\n";
    auto time3 = std::chrono::steady_clock::now();
    cout << std::chrono::duration_cast<std::chrono::seconds>(time3 - time2).count() << endl;
    
    mtx.unlock();
return 0;
// 输出：
    // lock success.
    // 0  // 说明0s就lock了
    // failed.
    // 5  // 等了5s还是没锁住，return false。
}
```

3.2假设有多块“共享资源”，arr1,arr2...，给每块“共享资源”安排一个 std::mutex 对象

mtx1 用来锁定 arr1，mtx2 用来锁定 arr2。

不同的对象，各有一个 mutex，独立地上锁，可以避免不必要的锁定，提升高并发时的性能。

还用了一个 {} 包住 std::lock_guard，限制其变量的作用域，从而可以让他在 } 之前解构并调用 unlock()，也避免了和下面一个 lock_guard 变量名冲突。


**图 13｜代码截图：两个 vector 分别使用 mutex** — [查看原始截图](images/image13.png)


```cpp
#include <iostream>
#include <string>
#include <thread>
#include <vector>
#include <mutex>

int main() {
    std::vector<int> arr1;
    std::mutex mtx1;
    std::vector<int> arr2;
    std::mutex mtx2;

    std::thread t1([&] {
        for (int i = 0; i < 1000; i++) {
            {
                std::lock_guard grd(mtx1);
                arr1.push_back(1);
            }
            {
                std::lock_guard grd(mtx2);
                arr2.push_back(1);
            }
        }
    });
    std::thread t2([&] {
        for (int i = 0; i < 1000; i++) {
            {
                std::lock_guard grd(mtx1);
                arr1.push_back(2);
            }
            {
                std::lock_guard grd(mtx2);
                arr2.push_back(2);
            }
        }
    });
    t1.join();
    t2.join();
    return 0;
}
```

std::unique_lock 和 std::mutex 具有同样的接口

其实 std::unique_lock 具有 mutex 的所有成员函数：lock(), unlock(), try_lock(), try_lock_for() 等。除了他会在解构时按需自动调用 unlock()。

因为 std::lock_guard 无非是调用其构造参数名为 lock() 的成员函数，所以 std::unique_lock 也可以作为 std::lock_guard 的构造参数！

这种只要具有某些指定名字的成员函数，就判断一个类是否满足某些功能的思想，在 Python 称为鸭子类型，而 C++ 称为 concept（概念）。比起虚函数和动态多态的接口抽象，concept 使实现和接口更加解耦合且没有性能损失。

std::thread t1([&] {

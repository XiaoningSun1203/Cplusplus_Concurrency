# 第 4 章：死锁

假设 “共享资源arr1”由锁 mtx1来保护，另一个“共享资源arr2”由锁 mtx2来保护.

// 此处缺少一个死锁的例子

解决死锁的方法：

方法1：一个线程不要同时持两个锁，而是先把一个锁unlock后，再lock另一个锁。

方法2：在2个不同的线程中，2个锁的上锁顺序相同，都是先mtx1.lock()再mtx2.lock()。而不是一个线程中先mtx1.lock()再mtx2.lock()，另一个线程中先mtx2.lock()再mtx1.lock()

如果没办法保证上锁顺序一致，可以用标准库的 std::lock(mtx1, mtx2, ...) 函数，一次性对多个 mutex 上锁。

他接受任意多个 mutex 作为参数，并且他保证在无论任意线程中调用的顺序是否相同，都不会产生死锁问题。

和 std::lock_guard 相对应，std::lock 也有 RAII 的版本 std::scoped_lock。只不过他可以同时对多个 mutex 上锁。


```cpp
#include <iostream>
#include <string>
#include <vector>
#include <thread>
#include <mutex>

using namespace std;

int main()
{
    std::mutex mtx1;
    std::mutex mtx2;
    std::vector<int> arr1;
    std::vector<int> arr2;
    
    std::thread t1([&] {
        for (int i = 0; i < 100; ++i)
        {
            mtx1.lock();
            arr1.push_back(1);
            
            mtx2.lock();
            arr2.push_back(2);

            std::this_thread::sleep_for(std::chrono::seconds(1));
            std::cout << "t1 arr1.size = " << arr1.size() << std::endl;
            std::cout << "t1 arr2.size = " << arr2.size() << std::endl;
            
            mtx2.unlock();
            mtx1.unlock();
        }
    });
    
    std::thread t2([&] {
        for (int i = 0; i < 100; ++i)
        {
            mtx2.lock();
            arr2.push_back(2);
            
            mtx1.lock();
            arr1.push_back(1);

            std::this_thread::sleep_for(std::chrono::seconds(1));
            std::cout << "t2 arr1.size = " << arr1.size() << std::endl;
            std::cout << "t2 arr2.size = " << arr2.size() << std::endl;
            
            mtx1.unlock();
            mtx2.unlock();
        }
    });
    
    t1.join();
    t2.join();
    std::cout << "function end\n";
    return 0;
}
```

假设线程只有一个锁mtx，主线程上了锁之后，又调用了func()，func()也需要上锁。而 func()看到mtx已经lock，于是开始等待mtx unlock。func()不知是调用它的主线程上的锁，func()陷入等待后,主线程的unlock()永远得不到调用。


```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex mtx;

void func()
{
    mtx.lock();  // 如果在此处try_lock(),结果是返回false。
    // do something
    mtx.unlock();
}

int main()
{
    mtx.lock();
    func();
    mtx.unlock();
    std::cout << "func finish\n";
    return 0;
// 结果是：卡死
}
```

遇到这种情况最好是把 func() 里的 lock() 去掉，并在其文档中说明：“func() 不是线程安全的，调用本函数之前需要保证某 mutex 已经上锁。

如果实在不能改的话，可以用 std::recursive_mutex。他会自动判断是不是同一个线程 lock() 了多次同一个锁，如果是则让计数器加1，之后 unlock() 会让计数器减1，减到0时才真正解锁。但是相比普通的 std::mutex 有一定性能损失。


```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::recursive_mutex mtx;

void func()
{
    mtx.lock();  // 如果在此处try_lock(),结果是返回false。
    // do something
    mtx.unlock();
}
int main()
{
    mtx.lock();
    func();
    mtx.unlock();
    std::cout << "func finish\n";
    return 0;
// 输出：func finish
}
```

    std::mutex mtx;

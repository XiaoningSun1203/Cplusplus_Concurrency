# 第 7 章：原子操作

当两个线程访问不同的内存位置时，不存在任何问题。而另一种情况下，当两个线程访问同一个内存位置，你就要小心了。如果没有线程更新内存位置上的数据，那还好；只读数据不需要保护或同步。当有线程对内存位置上的数据进行修改，那就有可能会产生条件竞争。

经典案例：多个线程修改同一个计数器

多个线程同时往一个 int 变量里累加，这样肯定会出错，因为 counter += i 在 CPU 看来会变成三个指令：

指令1: 读取 counter 变量到 rax 寄存器;

指令2: rax 寄存器的值加上 1;

指令3: 把 rax 写入到 counter 变量;

即使编译器优化成 add [counter], 1 也没用，因为现代 CPU 为了高效，使用了大量奇技淫巧，比如他会把一条汇编指令拆分成很多微指令 (micro-ops)。

问题是，如果有多个线程同时运行，顺序是不确定的：

thread 1：读取 counter 变量，到 rax 寄存器

thread 2：读取 counter 变量，到 rax 寄存器

thread 1：rax 寄存器的值加上 1

thread 2：rax 寄存器的值加上 1

thread 1：把 rax 写入到 counter 变量

thread 2：把 rax 写入到 counter 变量

如果是这种顺序，最后 t1 的写入就被 t2 覆盖了，从而 counter 只增加了 1，而没有像预期的那样增加 2。

更不用说现代 CPU 还有高速缓存，乱序执行，指令级并行等优化策略，你根本不知道每条指令实际的先后顺序。


```cpp
#include <iostream>
#include <thread>

int main()
{
    int counter = 0;
   
    std::thread thread1([&] {
        for (int i = 0; i < 100; ++i) {
            counter += 1;
        }
    });
   
    std::thread thread2([&] {
        for (int i = 0; i < 100; ++i) {
            counter += 1;
        }
    });
   
    thread1.join();
    thread2.join();
   
    std::cout << counter << std::endl;
return 0;
// PPT讲义上输出：18142
}
```

暴力解决：用 mutex 上锁

这样的确可以防止多个线程同时修改 counter 变量，从而不会冲突。

问题：mutex 太过重量级，他会让线程被挂起，从而需要通过系统调用，进入内核层，调度到其他线程执行，有很大的开销。

可我们只是想要修改一个小小的 int 变量而已，用昂贵的 mutex 严重影响了效率。


```cpp
#include <iostream>
#include <thread>
#include <mutex>
int main()
{
    int counter = 0;
    std::mutex mtx;
   
    std::thread thread1([&] {
        for (int i = 0; i < 10000; ++i) {
            mtx.lock();
            counter += 1;
            mtx.unlock();
        }
    });
   
    std::thread thread2([&] {
        for (int i = 0; i < 10000; ++i) {
            mtx.lock();
            counter += 1;
            mtx.unlock();
        }
    });
   
    thread1.join();
    thread2.join();
   
    std::cout << counter << std::endl;
return 0;
// 20000
}
```

建议用 atomic：有专门的硬件指令加持


**图 19｜汇编截图：lock xadd 指令** — [查看原始截图](images/image19.png)


```asm
lock xadd %eax,(%rdx)
```

可以用更轻量级的 atomic，对他的 += 等操作，会被编译器转换成专门的指令。

CPU 识别到该指令时，会锁住内存总线，放弃乱序执行等优化策略（将该指令视为一个同步点，强制同步掉之前所有的内存操作），从而向你保证该操作是原子 (atomic) 的（取其不可分割之意），不会加法加到一半另一个线程插一脚进来。

对于程序员，只需把 int 改成 atomic<int> 即可，也不必像 mutex 那样需要手动上锁解锁，因此用起来也更直观。


```cpp
#include <iostream>
#include <thread>
#include <atomic>

int main()
{
    std::atomic<int> counter = 0;
   
    std::thread thread1([&] {
        for (int i = 0; i < 10000; ++i) {
            counter += 1;
        }
    });
   
    std::thread thread2([&] {
        for (int i = 0; i < 10000; ++i) {
            counter += 1;
        }
    });
  
    thread1.join();
    thread2.join();
 
    std::cout << counter << std::endl;
    return 0;
}
```

NOTE：请用 +=，不要让 + 和 = 分开


```cpp
counter = counter + 1;  // 错，不能保证原子性
```


```cpp
counter += 1;           // OK，能保证原子性
```


```cpp
counter++;              // OK，能保证原子性
```


**图 20｜代码截图：atomic 的两次操作不是整体原子操作** — [查看原始截图](images/image20.png)


```cpp
std::atomic<int> counter = 0;
// 两个线程中均执行以下操作：
counter = counter + 1;
```

除了用方便的运算符重载之外，还可以直接调用相应的函数名，比如：

fetch_add 对应于 +=

store 对应于 =

load 用于读取变量 值


```cpp
#include <iostream>
#include <thread>
#include <atomic>

int main()
{
    std::atomic<int> counter;
    counter.store(0);
   
    std::thread thread1([&] {
        for (int i = 0; i < 10000; ++i) {
            counter.fetch_add(1);
        }
    });
   
    std::thread thread2([&] {
        for (int i = 0; i < 10000; ++i) {
            counter.fetch_add(1);
        }
    });
   
    thread1.join();
    thread2.join();
   
    std::cout << counter.load() << std::endl;
    return 0;
}
```

# 第 1 章：线程

进程与线程

进程是一个应用程序被操作系统拉起来加载到内存之后从开始执行到执行结束的这样一个过程。简单来说，进程是程序（应用程序，可执行文件）的一次执行。比如双击打开一个桌面应用软件就是开启了一个进程。

线程是进程中的一个实体，是被系统独立分配和调度的基本单位。也有说，线程是CPU可执行调度的最小单位。也就是说，进程本身并不能获取CPU时间，只有它的线程才可以。

从属关系：进程 > 线程。一个进程可以拥有多个线程。

每个线程共享同样的内存空间，开销比较小。

每个进程拥有独立的内存空间，因此开销更大。

对于高性能并行计算，更好的是多线程。（之所以是多线程而不是多进程，是因为高性能并行计算要访问同样的数据。）

Q：若线程等待某项条件成立或某一状态出现，而无法继续处理任务，就称它被阻塞。

Q：什么是异步？主线程可以与子线程进度不同。

“同步”：需要等子线程的结果返回才能继续运行。

“异步”：不需要等子线程的结果返回就可以继续运行。

为什么需要多线程：无阻塞多任务

我们的程序常常需要同时处理多个任务。比如浏览器在后台下载文件的同时，用户仍然可以用鼠标操作其 UI 界面。没有多线程的话，就必须等文件下载完了才能继续和用户交互。在下载完成之前，整个界面都会处于“未响应”状态(阻塞状态)，用户想做别的事情就做不了。


```cpp
#include <iostream>
#include <thread>
#include <string>

void download(std::string file) {
    for (int i = 0; i < 10; i++) {
        std::cout << "Downloading " << file
                  << " (" << i * 10 << "%)..." << std::endl;
        std::this_thread::sleep_for(std::chrono::milliseconds(400));
    }
    std::cout << "Download complete: " << file << std::endl;
}

void interact() {
    std::string name;
    std::cin >> name;
    std::cout << "Hi, " << name << std::endl;
}

int main() {
    download("hello.zip");
    interact();
    return 0;
}
```

现代 C++ 中的多线程：std::thread

C++11 开始，为多线程提供了语言级别的支持。他用 std::thread 这个类来表示线程。

std::thread 构造函数的参数可以是任何可调用类型(函数指针、函数对象、lambda等)。

当那个线程启动时，就会执行这个 “可调用类型” 里的内容。这样就可以一边和用户交互，一边在另一个线程里慢吞吞下载文件了。

有了多线程的话，文件下载和用户交互分别在两个线程，同时独立运行。从而下载过程中也可以响应用户请求，提升了体验。 实现了无阻塞

可是发现一个问题：我输入完 pyb 以后，他的确及时地和我交互了。但是用户交互所在的主线程退出后，文件下载所在的子线程，因为从属于这个主线程，也被迫退出了。 并没有实现异步


```cpp
int main() {
std::thread t1([&] {
download("hello.zip");
});
interact();
return 0;
}
```

std::thread 的解构函数会销毁线程

作为一个 C++ 类，std::thread 同样遵循 RAII 思想和三五法则：因为管理着资源，他自定义了解构函数，删除了拷贝构造/赋值函数，但是提供了移动构造/赋值函数。

因此，当 t1 所在的函数体退出时，就会调用 std::thread 的解构函数，这会销毁 t1 线程的句柄。当t1销毁时，download()指向的栈也被销毁。

所以，download() 函数才会出师未捷身先死——还执行完线程就被销毁了。


```cpp
void download(std::string file) {
    for (int i = 0; i < 10; i++) {
        std::cout << "Downloading " << file
                  << " (" << i * 10 << "%)..." << std::endl;
        std::this_thread::sleep_for(std::chrono::milliseconds(400));
    }
    std::cout << "Download complete: " << file << std::endl;
}

void interact() {
    std::string name;
    std::cin >> name;
    std::cout << "Hi, " << name << std::endl;
}
void myfunc()
{
std::thread t1([&] {
download("hello.zip");
});
}  // 退出函数体时，会销毁t1线程的句柄

int main() {
    myfunc();
    interact();
    return 0;
}
```

实现异步的方法：


```cpp
t1.join();
```

主线程等待子线程结束。


```cpp
t1.detach();
```

分离std::thread对象t1与线程，使得线程的生命周期不再由当前的std::thread对象t1来管理，即使t1因为离开作用域而被销毁，线程也不会被销毁。

为了让t1不再因为离开作用域而被std::thread类的解构函数销毁，一共有两种方法：

解决方案1：

用detach() 分离该线程——意味着线程的生命周期不再由当前 std::thread 对象t1管理，而是在该线程结束之后自动销毁自己。

•  t1.detach(); 之后，t1 本身不再持有任何线程资源。

•  t1 变成一个“空” std::thread，即 t1.joinable() 返回 false。

•  不能再对 t1 调用 .join() 或 .detach()，否则会触发异常。

不过即使detach t1，还是会在所在进程退出的时候(main()函数结束时)导致该线程t1退出？？？？？。


```cpp
int main ()
{
    std::thread t1([&]{
       download("hello.zip"); 
    });
    interact();
    t1.detach();
    cout << "leave main()...." << endl;
    return 0;
}
```
